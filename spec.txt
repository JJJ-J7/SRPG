■このプロジェクトの基本的な概要

マス目上のキャラクターを操作して遊ぶ、シミュレーションRPGゲームである。

■基本的な制約や用語など

・ゲームの描画自体はPhaserを使用するが、UIはできるだけ UIComponents を利用したい。
・各Phaserシーンの基本的な構造やUIの実装は、既存のSceneMainMenuを参考にしてほしい。
・ダイアログは、SceneUiTest2.js にあるサンプルダイアログを参考にしてほしい。
・セーブは IndexedDB を利用する
・「プレイヤー」は、「ユーザー」と「CPU（ユーザーの対戦相手となる敵）」の総称である

■メインメニュー

・メインメニュー（SceneMainMenu.js のシーン） には、ゲームの新規開始ボタン(this.btnNewGame)と、ゲームの再開ボタン(this.btnContinue)が置いてある。
・新規開始ボタンを押すと、新しくゲームを始めることができ、SceneSelectTribe.js のシーンに遷移する。
・ゲームの再開ボタンを押すと、SceneGame.js のシーンに遷移して、前回の状態のロードをはじめる。

■部族選択シーン

・部族選択シーン（SceneSelectTribe.js のシーン）では、N個の部族から1つの部族をプレイヤーが選択できる。
・メインメニューに戻るためのキャンセルボタンも配置される
・まずはN=12個の部族をテスト用に配置する。このとき、UI_GridContainer を使用し、各部族のボタンはUI_ImgTxtBtnを使用する。
    ・部族のボタン画像は、後で定義する部族の「代表的な画像（小）」を表示する。
    ・部族のボタンテキストは、後で定義する部族の「部族名」を表示する。
・部族をタッチすると、部族のプレビューダイアログが出現する。このダイアログでは、部族の情報の確認と、OKボタン、キャンセルボタンが配置されている
    ・部族の情報としては、後で定義される以下の情報を表示する
        ・部族名
        ・部族の説明文
        ・代表的な画像（大）
    ・OKボタンを押すと、モード選択シーン（SceneSelectMode.js のシーン）に遷移する
    ・キャンセルボタンを押すと、ダイアログを閉じる
・部族は以下のようなプロパティを持つ。ただし、これらの定義は SceneSelectTribe.js 内ではなく、外部のJSファイルに切り出してほしい（メンテしやすいように。）
    ・部族名
    ・部族の説明文
    ・代表的な画像（小）
    ・代表的な画像（大）
    ・所属ユニット（これは後で定義される）
    ・部族スキル（これは後で定義される）
    ・初期ユニット
    ・初期都市
    ・初期資源
    ・色

■モード選択シーン

・モード選択シーン（SceneSelectMode.js のシーン）では、ゲームを開始するための各種設定を行う。
ここで設定した設定は、ゲームに利用される。
・このシーンには以下のUIが配置されている
    ・ゲーム開始ボタン（SceneGame.js のシーンに遷移）
    ・部族選択シーンに戻るボタン
    ・以下の各種設定ボタン（これらは、横のUI_GridContainer。有効になってる設定の色が変わる）
        ・マップサイズ（8x8, 16x16, 20x20, 32x32）
        ・マップタイプ（大陸, 内陸湖, 群島）
        ・敵CPUの数（1~16）
        ・敵CPUの強さ(Monkey, Easy, Normal, Hard, Inferno)

■ゲームシーン

・新規ゲーム開始した場合は、以下のように、プレイヤーと2Dマップを生成する。
    ・プレイヤー数は、ユーザー＋モード選択シーンで選んだ「敵CPUの数」の合計
・メインメニューで「再開ボタン」を押した場合は、前回のセーブをロードしてマップや、プレイヤー、CPUの情報を復元する。

・プレイヤーは以下の情報をもつ
    ・何番目のプレイヤーか
    ・操作権を持つのが、ユーザーなのかCPUなのか
    ・部族
        ・ユーザーの部族は、「部族選択シーン」で選んだもの
        ・CPUの部族は、ランダムに選ばれる
    ・強さ
        ・モード選択シーンで選んだ「敵CPUの強さ」
・2Dのマップは以下の仕様である
    ・モード選択シーンで設定した縦と横の数のタイル（マス目）で構成される
    ・タイルごとに以下のレイヤー（情報）をもつ。各情報は後で定義する
        ・「地形」（一番下に表示）
        ・「施設」（地形の上に表示）
        ・「ユニット」（地形と施設の上に表示）
        ・「視界」（地形、施設、ユニットの上に表示）
・マップを生成するときには
    ・「地形」の生成
        ・モード選択シーンで設定した「マップタイプ」に応じて、乱数シードを使って生成する
        ・TODO：都市の位置を決め、その周囲をマップタイプに応じて埋めていくイメージ
    ・「施設の生成」
        ・生成済みの「地形」のなかで、「都市建設可能」の属性がついた地形にプレイヤー数x2の数の都市を配置する
            ・ただし、ある都市の周囲8マスには都市を配置できない
            ・もし上記ルールでこれ以上都市を配置できなくなったときは、都市の配置を終了する
        ・プレイヤーごとに、上記の都市のうちのランダムな1つをその部族の「初期都市」として所有する
        ・所有する都市上には、そのプレイヤーの部族の1体の「初期ユニット」が生成される
        ・所有する都市と、それを囲む8マス（合計9マス）の「地形」は、そのプレイヤーの所有物になる
・ゲームの流れ
    ・ターン制で進行する
    ・ユーザーのターン → CPU0のターン → CPU1のターン → … → ユーザーのターン、という順番で進行する
    ・ターンの開始時、プレイヤーは、その領土内の「地形」「施設」「ユニット」から「資源」を得る
        ・資源はあとで定義する
    ・ターンの間、プレイヤーは、「ユニット」「施設」「地形」を操作できる
        ・ユーザーは、1つのタイルをタッチするたびに「ユニット」「施設」「地形」それぞれの操作ダイアログが順番に出現する
            ・ただし、そのタイルに「ユニット」や「施設」が存在しなければ、対応する操作ダイアログは出ない。
        ・別のタイルをタッチした場合は、以前のタイルの操作ダイアログは閉じる
    ・ユーザーは「ターン終了ボタン」を押すことでターンを終了できる
    ・CPUたちは、そのAIがターンの終了を判断する
    ・ターンの終了時に、ゲームの状態はセーブされる。セーブ内容は
        ・ゲームの設定
        ・誰のターンか？
        ・ターン数
        ・マップの情報
        ・プレイヤー情報
    ・ユーザーがマップ上のすべての「都市」を所有できた場合が勝利になる。
        ・勝利後、結果ダイアログを表示する
            ・そのダイアログ上には、ゲームにかかったターン数と、終了ボタンが表示される
            ・終了ボタンを押すと、メインメニュー（SceneMainMenu.js のシーン）に戻る
    ・ユーザーの所有する「都市」が0個になった場合敗北になる。
        ・敗北時、結果ダイアログを表示する
            ・そのダイアログ上には、ゲームにかかったターン数と、終了ボタン、観戦ボタンが表示される
            ・終了ボタンを押すと、メインメニュー（SceneMainMenu.js のシーン）に戻る
            ・観戦ボタンを押すと、敗北ダイアログを閉じてCPU同士の対戦を続けて眺めることができる
                ・いずれかのCPUがすべての「都市」を所有できた場合に、観戦終了になる。
                    ・観戦終了時、結果ダイアログを表示する
                        ・そのダイアログ上には、ゲームにかかったターン数と、終了ボタンが表示される
                        ・終了ボタンを押すと、メインメニュー（SceneMainMenu.js のシーン）に戻る
            
■「マップタイプ」

・マップタイプとは、地形を生成するときに、どの地形をどれぐらい生成するかを定義した概念である。

・マップタイプの種類
    ・大陸

■「地形」

・地形とは、タイルの情報の1種類で、概念的にはユニットや施設が上に乗る「地面」である。

・地形は以下の情報をもつ
    ・所有者となるプレイヤー
    ・地形の種類（あとで定義する）
    ・地形の状態（これは地形の種類ごとに異なる）

・地形の操作（ダイアログ）
    ・地形の操作ダイアログは、ユーザーのターンに地形をタッチしたときに表示されるダイアログである（前述のとおり）
    ・なお、CPUのターンには、CPUは操作ダイアログを表示しないが、CPUが地形に対して可能な操作は以下と同様である。
    ・ユーザーが所有する「地形」であれば、その「地形の種類」で定義された「所有者による操作」のボタン群が表示される
    ・CPUが所有する「地形」であれば、その「地形の種類」で定義された「未所有者による操作」のボタン群が表示される
    ・どのプレイヤーも所有してない「地形」であれば、その「地形の種類」で定義された「自由地操作」のボタン群が表示される

・地形の種類（外部のJSファイルに切り出される）
    ・「平野」
        ・名前：平野
        ・説明文：ただ広い平野
        ・歩きにくさ：2
        ・地形ダメージ：0
        ・都市建設可能：true
        ・道状態：false
        ・所有者による操作
            ・施設の「畑」の建設
            ・道状態をtrueに変更
        ・未所有者による操作
            ・なし
        ・自由地操作
            ・道状態をtrueに変更

■「視界」

・視界とは、各プレイヤーがマップのタイルの情報を把握できるかを示す概念である。
・タイルごと、かつプレイヤーごとに true または false の値をもつ。初期値はすべてfalseである。
・ユーザーは、視界が true のタイルは画面上で見て操作をすることができる。false の タイルは、画面上で雲の画像で隠されるし、操作もできない。
・CPUのAIは、視界が true のタイルを使って判断をする。false のタイルは判断を行わない。
・ユニットや施設は、それぞれ定義された「視距離」パラメータを持ち、「視距離」内のタイルの「視界」は、ユニットや施設の所有者にとって true に変わる。

■「資源」

・資源は、数字の変数であり、複数の種類がある。
・資源は、プレイヤーが、「ユニット」「施設」「地形」に対して操作を行うときに必要なコストである。
・プレイヤーは、資源を所有することができる
・また、「ユニット」「施設」「地形」や、その中で定義された各種操作では、資源を生成することができる。
